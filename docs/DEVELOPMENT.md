## 技术决定

当前机器已安装并激活 Unity 6000.6.0f1（含 Windows Standalone Support），同时有 .NET Framework C# 编译器但没有独立 .NET SDK。因此继续使用同一份 Core 源码，同时提供轻量原生试玩宿主与 Unity 3D 宿主。原生预览器不承担正式网络架构。

Core 不依赖 Unity，位置使用每格1000单位的整数坐标、20Hz固定步长。寻路是四方向带墙体成本的 A*；部队实际拆墙后才能穿过对应路径。选目标有兵种偏好，但尚未做整条路径成本参与目标排序，也没有部队避让。

远征营每座提供45点基础营位，每升一级增加15点；多座营地叠加。队列一次训练一名单位，时间戳写入存档，回到聚落后补算真实时间；战斗中不显示训练完成。训练和预设编队都在规则层同时检查资源与“成军 + 排队”总营位，失败不会部分扣款。三套预设按当前就绪和排队人数计算缺额，可在战后补齐。出征把成军阵容转移到 Battle；结算只消耗真正部署的单位，剩余待命部队返回村庄。战斗中保存会序列化出征前编队副本，防止异常重启读取空营地。

关卡预设偏易，主要用于验证行为。自动化全兵力进攻可以通过全部10关，不能据此宣称数值平衡完成。尚未设置失败次数、难度自适应或付费设计。

`Core/ModelGeometry.cs` 定义引擎无关的三维面和顶点色，继续为原生预览器及 Unity 的碰撞、连续城墙提供几何。Unity `ModelViews.cs` 优先加载 KayKit/Quaternius 三维建筑和兵种；`ImportedClipAnimator` 播放导入角色原生动作，`ArticulatedModelAnimator` 驱动铁卫、翼骑、炼金师和风暴塔的骨骼/部件动作，`ModelActionAnimator` 为其余对象保留轻量动作兜底。原生客户端仍使用程序化模型，两套宿主共享玩法规则但不要求表现完全相同。

建筑上限统一由 `Rules.BuildLimit` 按议事堡等级决定，UI 只是展示，实际限制在 `GameSession.Build`。不在读档校验中强制新数量上限，避免删除旧版建筑。拆除先收取已有收益，再按建设和历次升级总投入返还 50%；保护议事堡，清空移动历史。当前 XML 存档版本为 2；旧版风暴塔 760 满血仅在读档时按已知历史数值适配新版 900 满血，其他异常值继续拒绝。

图鉴和战斗说明读取真实的 `TroopSpec` 数值，不使用另一套展示数值。教学引导铁卫吸引火力、破城手开墙、先锋跟进、游侠后排输出；首次出征教学按进程显示一次，不新增存档字段。模态面板暂停本地战斗，并阻止点击穿透。

## 下一步顺序

1. 完成一轮真实鼠标试玩，逐项记录投兵、战斗结算、返乡训练、建筑操作和图鉴预览的问题；自动烟测不能替代手感验收。
2. 用多套同营位编队完成前中后期关卡，采集胜率、破坏率、剩余单位和战斗用时，据此微调平衡。
3. 继续制作或挑选更成熟的翼骑坐骑、铁卫盔甲和炼金师投掷道具；现有 CC0 候选中画风明显退步的模型不直接引入。
4. 加入部队避让、更完善的路径目标评分和训练队列批量操作。
5. 设计独立在线进度，接入账号、基地快照、匹配、版本化战斗凭据、服务端复算和事务结算。

## 未解决限制

- Unity 自动构建和17项渲染烟雾测试已通过，但还没有完成整套 Unity 人工交互回归、10关逐关人工试玩或其他电脑兼容性测试。
- `tools/build-unity.ps1` 提供 Check / Prepare / Build / Package，固定工程版本、独立日志、失败退出码和本轮成功标记检查；打包会排除 Unity 标记为不可发布的备份目录。
- 原生试玩的布局撤销只覆盖单个建筑移动；没有多选框选或批量撤销建造。
- 资源依赖本地时间，存档未加密；不应用于联网排名或付费经济。
- 同环境复现测试不是跨平台确定性证明，也没有完成命令文件导入回放功能。
- 本地只保留上一份存档；未实现跨进程存档写锁或云同步。
- 没有正式性能指标；不能把截图生成耗时当作帧率。
- 训练依赖客户端本地时钟，适合离线原型，不适合联网经济；联网版必须由服务端签发并结算时间。
- 当前 Unity 美术已有可旋转的三维模型与角色骨骼动作，但铁卫、翼骑和炼金师的角色细节、翼骑坐骑、战斗特效及完整 PBR 贴图仍未达到最终美术标准。
